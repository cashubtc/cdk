# Migration notes for v0.19

## SQL transaction resource wrappers

Custom SQL resource wrappers used with `ConnectionWithTransaction` must also
implement `cdk_sql_common::database::TransactionResource`. A resource dropped
with reuse disabled must be closed rather than pooled. The built-in pool keeps
this flag separate from driver health, and only re-enables reuse after an
acknowledged commit or rollback. Best-effort Drop cleanup is bounded to five
seconds; failed or cancelled cleanup discards the connection. Discarding the
sole connection of a private in-memory SQLite database also discards that
ephemeral database; use file-backed storage for durable wallet data.

## LND backend initialization

The LND backend now calls `GetInfo` during `Lnd::new` to cache the node pubkey
and invoice network. Initialization requires a reachable LND node and a
macaroon that permits `info:read` or the specific `/lnrpc.Lightning/GetInfo`
RPC. This applies whether self-payments are enabled or disabled.

The standard `admin.macaroon` already permits this call. Before upgrading,
update custom restricted macaroons to permit `GetInfo` in addition to their
existing permissions. Missing permission or invalid node information now
returns an initialization error before the backend accepts payments.

The cached information lets the backend reject invoices for another network
and disallowed self-payments locally. Existing paid or pending payments are
reconciled before dispatch validation. These checks prevent new rejected
payments from getting stuck; they do not resolve previously pending quotes.

## Wallet trait removal

The `cdk_common::wallet::Wallet` trait (often imported as `WalletTrait`) and
its implementations for the CDK and FFI wallets have been removed. Use the
inherent methods on `cdk::wallet::Wallet` or `cdk_ffi::wallet::Wallet` instead.
Remove trait imports and replace trait-qualified calls with inherent method
calls. Downstream generic bounds and custom implementations must migrate to
concrete wallet types or an application-owned trait.

The trait aliases `check_mint_quote`, `mint_unified`, and
`melt_human_readable` map to `check_mint_quote_status`, `mint`, and
`melt_human_readable_quote`, respectively. For FFI wallets, use the exported
method signatures and FFI types; for example, rate limiting is configured
through `set_rate_limit`. For native wallets, replace
`set_rate_limiting_config(None)` with `disable_rate_limiting()` and pass the
configuration directly to `set_rate_limiting_config` when enabling pacing.
The exported UniFFI API is unchanged.
