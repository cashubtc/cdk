# Migrating to CDK v0.19

## Nostr payment request validation

`WalletRepository::wait_for_nostr_payment(info)` now always validates incoming
payments against the original request: request ID, unit, amount after fees,
accepted mints, and spending conditions. Invalid payments are ignored while
listening; operational and indeterminate redemption failures are returned.

Keep passing the `NostrWaitInfo` returned by `create_request` to the existing wait
method. Applications with their own Nostr transport can pass that information
and a decoded payload to `receive_nostr_payment(&info, payload)`.

`NostrWaitInfo` replaces the `mints` and `mint_preferred` fields with `request`
(the complete `PaymentRequest`) and `trusted_mints` (the local trust snapshot).
Update manual struct construction accordingly. Do not derive these constraints
from an incoming payload. Creating a Nostr request requires explicitly listed
or locally configured mints for its unit; an omitted mint list defaults to the
configured mints. Preferred mints never grant trust to an unknown mint.

CLI records created before the full request constraints were saved cannot be
validated safely and must be recreated.
