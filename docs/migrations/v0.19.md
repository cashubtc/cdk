# Migration Guide: v0.18.x to v0.19.0

## Summary

The `[limits]` section gained ceilings for the `/v1/ws` endpoint and for the
mint's subscription manager. The library crates carry four breaking signature
changes that go with them; see [Library API Changes](#library-api-changes).

Almost no configuration change is required. Every new key has a default, so an
applied v0.18 configuration document that does not carry them keeps working and
reads the shipped defaults. The exception is a `max_inputs` or `max_outputs` of
zero, which v0.18 accepted and v0.19 refuses at startup; see [Transaction
Limits Must Be Nonzero](#transaction-limits-must-be-nonzero). The limits are
enforced from the first v0.19 start, not only once an operator opts in by
writing the keys, so a mint that today relies on unbounded WebSocket or
subscription use should review the defaults before upgrading.

To change a default, edit the import document and stage it the usual way:

```bash
cdk-mintd config validate --file /path/to/changed-config.toml
cdk-mintd config apply --file /path/to/changed-config.toml
```

Restart the daemon to activate the replacement.

The LND backend also gained an initialization requirement that is independent
of the limits; see [LND Backend Initialization](#lnd-backend-initialization).

## LND Backend Initialization

The LND backend now calls `GetInfo` during `Lnd::new` to cache the node pubkey
and invoice network. Initialization requires a reachable LND node and a
macaroon that permits `info:read` or the specific `/lnrpc.Lightning/GetInfo`
RPC. This applies whether self-payments are enabled or disabled.

The standard `admin.macaroon` already permits this call. Before upgrading,
update custom restricted macaroons to permit `GetInfo` in addition to their
existing permissions. Missing permission or invalid node information now
returns an initialization error before the backend accepts payments.

The cached information lets the backend reject invoices for another network
and disallowed self-payments locally. Existing paid or pending payments are
reconciled before dispatch validation. These checks prevent new rejected
payments from getting stuck; they do not resolve previously pending quotes.

## Transaction Limits Must Be Nonzero

`cdk-mintd` now refuses to start on `max_inputs = 0` or `max_outputs = 0`,
naming the key to fix. v0.18 accepted both, then rejected every transaction
carrying an input or an output, so a configuration that set either to zero was
already serving nothing. Give each the number of inputs or outputs the mint
should accept, or delete the key and take the default.

This check lives in `cdk-mintd`, not in `MintLimits`. An embedder constructing a
`Mint` directly is responsible for its own transaction limits; the pub/sub
fields are validated by the constructor.

## Review the New WebSocket Limits

The `/v1/ws` ceilings are a process-wide connection count, subscriptions and
filters per connection, a per-connection request budget, a message size cap, and
the keepalive and idle timeouts. The shipped defaults are safe for a public
mint.

There is no per-client connection cap. A reverse proxy already sees the real
client address and is the right place to enforce that policy.
`ws_max_connections` bounds the mint as a whole.

`cdk-mintd` refuses to start on limits it could not serve, naming the key to
fix: a zero where zero means "refuse everything", a
`ws_max_request_burst_units` or `ws_max_topics_per_connection` too small to
admit one `ws_max_filters_per_subscription` request, or a
`ws_ping_interval_secs` that is not shorter than `ws_idle_timeout_secs` and so
leaves a quiet client no window to answer a ping. See
`crates/cdk-mintd/example.config.toml` for every key and its default.

## Review the New Subscription Limits

The subscription-manager ceilings are `pubsub_max_topics`, which bounds the
topic index across the whole mint, `pubsub_max_concurrent_backfills`, which
bounds how many subscriptions read their initial state at once, and
`pubsub_max_quote_checks_per_backfill`, which bounds how many payment-backend
round trips one of those reads may make.

`pubsub_backfill_timeout_secs` bounds how long one of them may hold a slot. The
check budget bounds the number of round trips, not their duration, so a stalled
payment backend could otherwise let a handful of subscriptions occupy every
slot. A backfill that runs out of time sends no initial state and logs it; the
subscription stays live and receives every later event, and a payment the
backend has already reported is still committed.

Each of these keys must be greater than zero, and `cdk-mintd` refuses to start
otherwise, naming the key to fix. Zero is not an off switch: a zero
`pubsub_max_quote_checks_per_backfill` in particular would serve every backfill
from storage without asking the payment backend, so a client could keep seeing a
quote as pending after it was paid.

## Library API Changes

Four signatures changed in `cdk`, `cdk-common` and `cdk-axum`. A `cdk-mintd`
operator is unaffected by this section; it applies to code depending on the
library crates.

### `Mint::new` and `Mint::new_with_auth` take `MintLimits`

The two `max_inputs: usize, max_outputs: usize` parameters collapsed into a
single `MintLimits`, which also carries the pub/sub ceilings.

```rust
// Before
let mint = Mint::new(
    mint_info,
    signatory,
    localstore,
    payment_processors,
    1000,
    1000,
)
.await?;
```

```rust
// After
use cdk::mint::MintLimits;

let mint = Mint::new(
    mint_info,
    signatory,
    localstore,
    payment_processors,
    MintLimits::default(),
)
.await?;
```

`MintLimits::default()` keeps the old transaction ceiling of 1000 inputs and
1000 outputs. The pub/sub defaults are new, so a mint built this way also picks
up a finite topic index and the backfill ceilings; those are the same defaults
`cdk-mintd` ships. To set the transaction limits explicitly:

```rust
let limits = MintLimits {
    max_inputs: 64,
    max_outputs: 64,
    ..MintLimits::default()
};
```

Both constructors now validate the pub/sub fields and return
`Error::PubsubLimits` on a value they could not serve, so a mint that would
wedge itself fails to construct rather than at the first subscription.

`MintBuilder` is source compatible: `with_limits(max_inputs, max_outputs)` is
unchanged. The pub/sub ceilings are reached through the new
`with_pubsub_limits(PubsubLimits)`.

### `Mint::check_mint_quote_paid` takes the quote by value

It used to mutate a borrowed quote in place. It now consumes the quote and hands
back the updated one, so a caller whose task may be cancelled can move the whole
check onto a task of its own.

```rust
// Before
let mut quote = load_quote().await?;
mint.check_mint_quote_paid(&mut quote).await?;
println!("{}", quote.state());
```

```rust
// After
let quote = load_quote().await?;
let quote = mint.check_mint_quote_paid(quote).await?;
println!("{}", quote.state());
```

The caller now has to own the quote, so a borrowed one needs a clone.

### `Spec::fetch_events` returns `Result<(), Error>`

Every `cdk_common::pub_sub::Spec` implementation breaks at compile time. An
implementation that cannot fail adds `Ok(())`.

```rust
// Before
async fn fetch_events(self: &Arc<Self>, topics: Vec<Self::Topic>, reply_to: Subscriber<Self>)
where
    Self: Sized,
{
    for topic in topics {
        reply_to.send(self.load(topic).await);
    }
}
```

```rust
// After
use cdk_common::pub_sub::Error;

async fn fetch_events(
    self: &Arc<Self>,
    topics: Vec<Self::Topic>,
    reply_to: Subscriber<Self>,
) -> Result<(), Error>
where
    Self: Sized,
{
    for topic in topics {
        reply_to.send(self.load(topic).await);
    }

    Ok(())
}
```

Returning `Err` leaves the subscription live and receiving new events; only the
state it held at the moment it subscribed is missing. That is how an
implementation reports an overrun of `PubsubLimits::backfill_timeout`, and
`Error::BackfillFailed` is the variant for it. `Pubsub` logs the error at `warn`
and keeps the subscription.

`Pubsub::subscribe` keeps its signature but gained a failure: it returns
`Error::TooManyTopics` once `PubsubLimits::max_topics` is reached. A caller that
treated every subscribe error as fatal should narrow its filters or retry
instead. The wallet's local relay is unaffected by default, since
`PubsubLimits::DEFAULT_MAX_TOPICS` is unbounded; a mint picks a finite budget.

### `create_mint_router_with_custom_cache` takes `WsLimits`

```rust
// Before
let router = create_mint_router_with_custom_cache(
    mint,
    cache,
    custom_methods,
    enable_info_page,
)
.await?;
```

```rust
// After
use cdk_axum::WsLimits;

let router = create_mint_router_with_custom_cache(
    mint,
    cache,
    custom_methods,
    enable_info_page,
    WsLimits::default(),
)
.await?;
```

The call now fails on limits it could not serve, with the same rules
`cdk-mintd` reports at startup. `create_mint_router` is unchanged and applies
`WsLimits::default()`.
