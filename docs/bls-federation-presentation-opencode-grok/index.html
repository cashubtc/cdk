    04 Why BLS exists before federation

    Verify against one K. Share k later.

    Secp DHKE works for one operator. It does not give threshold issuance that a vanilla wallet can still check.

    secp v1/v2 Y = H(secret) B_ = Y + rG C_ = k · B_ C = C_ − rK DLEQ proves knowledge of k BLS v3 B = r · H(secret) G1 C_ = k · B C = r⁻¹ · C_ e(C, G2) == e(H(secret), K) e(C_, G2) == e(B, K) G2 keys 96 B · G1 msgs 48 B DST CASHU_BLS12_381_G1_XMD:SHA-256_SSWU_RO_

    06 Crypto building blocks

    33, 48, or 96 bytes.

    Parse

    PublicKey is Secp / BlsG1 / BlsG2. Identity rejected. BLS scalars big-endian on the wire, reversed for bls12_381::Scalar.

    DHKE

    blind_message_for_version, pairing verify, batch via transcript Cashu_BLS_Batch_v1. v3 DLEQ is rejected in construct_proofs.

    Landmines

    Old secp helpers still panic on BLS: uncompressed, x-only, negate, to_scalar. Federation cleanup calls this out.

    07 Deterministic derivation

    Reject until it is Fr*.

    NUT-13 secrets reuse the v2 HMAC KDF for v3. Blinding factors add an attempt counter and parse as a canonical BLS scalar.

    "Cashu_KDF_HMAC_SHA256" || keyset_id || u64_BE(counter) || 0x01 || u32_BE(attempt) reject 0 · accept Fr*

    Mint amount keys evolved three times: hash child → reduce child → rejection-sample a second hardened index.

    for amount i: child = BIP32(i' / attempt') accept SecretKey::bls_from_slice unit test: live key is the two-level child

    08 End-to-end v3 proof

    Check the blind signature first.

    This walk is what later makes federation obvious. The public HTTP protocol does not change.

    1. Wallet picks the active keyset. If v3, all later crypto is BLS. Derives secret and r, blinds B = r · H(secret).
    2. Mint looks up amount key k, returns C_ = k · B, attaches no DLEQ.
    3. Wallet: e(C_, G2) == e(B, K) → unblind C = r⁻¹ · C_ → e(C, G2) == e(H(secret), K).
    289fe9e44 Early wallet code could construct a v3 proof and only check the unblinded pairing. The fix wired verify_bls_blind_signature into mint-response, restore, auth mint, and verify_token_signatures. If a v3 proof still carries DLEQ, reject it.

    Tokens still ordinary Cashu. ProofV4.dleq skipped if none. A v3 token must not encode "d": null.

    09 Mixed-curve safety

    Valid hex is not a secp key.

    A compressed G1 point is valid PublicKey::from_slice input. Before the fix, P2PK x_only_public_key() panicked.

    • P2PK / HTLC stay secp-only → NonSecp256k1Pubkey
    • Identity points rejected on G1 and G2 parse
    • Zero scalars rejected for r, mint keys, batch weights
    • NUT-00 batch vector is a unit test in nut01/bls.rs
    Fuzz had to change Random hex almost never decodes to a subgroup-correct BLS point. fuzz_bls_pubkey_in_conditions injects valid G1/G2 into nut10 data, pubkeys, refund_keys. fuzz_bls_dhke covers parse, DHKE, and batch-weight soundness.

    14 Alternative

    Multisig federates the token.

    BLS is not the only federation. Each member could return a full secp signature on the same B_. The wallet would keep a set. That is a real federation. It moves the threshold into the bearer object.

    Naive path t-of-n the way Bitcoin simulates a threshold with bare multisig. Receive, swap, melt, restore all have to understand the bundle. Token size and verify cost grow with t.
    BLS path Members still produce shares. The wallet reconstructs one ordinary Cashu proof before the token exists. The bearer object stays boring.

    Cashu cares about the second thing.

    15 Design fork

    Do not collapse the two secp designs.

    Bare multisig

    Each member has its own k_i. Wallet blinds once. Each returns a full C_i. A spendable proof carries t signatures. Token, verify, swap, melt, restore become federation-aware.

    Interpolated secp DHKE

    Share one k. Each returns C_i = k_i · B_. Wallet interpolates one secp proof. Algebra works. Proving the result is k · Y without anyone holding k does not — DLEQ needs the secret.

    Bitcoin can afford bare multisig because the coin lives in a UTXO that already names its script. Cashu cannot, because the coin is the signature.

    16 BLS threshold scheme

    Any t shares, one C.

    Classic Shamir-threshold BLS on Cashu’s blinded G1 message. Not many independent signatures. Not IETF aggregate-BLS on different messages.

    f(x) = k + a1 x + … + at-1 xt-1 k_i = f(i) K_i = k_i · G2 K = k · G2 signer ids: non-zero u16 (0 is the secret) B = r · H(secret) C_i = k_i · B e(C_i, G2) == e(B, K_i) λ_i(0) = Π (−j)/(i−j) C = Σ λ_i(0) · C_i = k · B

    17 Threshold-signing mix-and-match

    Independently valid shares are the attack.

    A share checks against K_i even if nobody else signed that B. Slide windows across the roster and you mint more than the quote paid. Not a BLS-math bug.

    18 Consensus before signing

    Agree on the envelope. Then sign.

    Treat AlephBFT as a black box. A member does not sign because it received HTTP. It signs because that exact envelope came out as accepted.

    envelope = { federation, kind: Swap, inputs, outputs } operation_id = hash(envelope) S_AB = hash(P1,P2 → A,B) S_BC = hash(P1,P2 → B,C) box accepts one P1,P2 spent · sign only A,B C is not in the operation

    Mint/melt lock on quote id. Swap locks when the first accepted op spends the inputs. Signing T below consensus C is safe only because shares are produced after accept.

    19 Data flow and transport

    Two planes. Same members.

    iroh:// is not a new protocol. It is the same HTTP-shaped Cashu and /federation/v1 traffic, tunneled. The split that matters is public fan-out vs private mesh.

    20 BLS DKG

    Nobody ever holds k.

    Dealer-free Pedersen DKG on the private plane. Every member contributes a polynomial. Joint secret is the sum of the constant terms. Same ceremony once per denomination.

    21 Challenges · SEC-2026-07-17-01

    Consensus does not bind client intent.

    A Byzantine member who saw the bearer proofs can rewrite the outputs and race that envelope first. Honest members cannot tell that X,Y were not the user’s.

    • Not a BLS bug. The shares are valid — for the wrong outputs.
    • Not mix-and-match. Only one operation wins; it is the attacker’s.
    • Not solved by fan-out. Fan-out is how the evil member learns the proofs.
    • Not solved by DKG. DKG protects k, not the user’s secrets.
    • NUT-11 SIG_ALL commits the owner to the exact outputs. Current code can bind it; it does not require it.
    Status Still a production blocker. Until SIG_ALL is required on every federated spend, do not describe this as safe against one malicious member.

    22 Funding backends

    Do not federate the printer and keep one piggy bank.

    A Cashu mint is two machines glued together. BLS issues proofs. Lightning or on-chain holds the reserves. If those quorums diverge, the smaller one is the real mint.

    Classical connectors fail

    One CLN / LND / BDK / Bark means one operator can mark a quote paid, refuse a melt, or sweep funds while the eCash ledger looks honest.

    Federated BDK

    Watch the chain, agree addresses and unsigned txs in the same box, jointly sign. One member can propose. It cannot move coins.

    Federated Bark

    Invoices and melts are consensus operations first. Claiming an HTLC is threshold custody, not “member 3’s CLN paid it.”

    Same roster, same T

    FROST on secp256k1. Different key, different curve, different job. Fakewallet / development_single_observation are tests. They reintroduce a king.

    23 FROST DKG

    Same roster. Different curve. Different job.

    Startup is not done until both ceremonies exist and every member confirms both public results. Secrets must not be mixed.

    BLS12-381

    25 Swap, step by step

    No Bitcoin. Still consensus-before-sign.

    One public POST /swap. Response looks like SwapResponse, but each member returns its BLS shares, not a finished mint signature.

    1. Wallet blinds A,B and fans the same request to every public_mint_url.
    2. Member wraps {inputs, witnesses, outputs}, hashes the envelope, does not sign.
    3. Admission rejects empty / duplicate / non-v3 / unbalanced before propose.
    4. Box accepts one winner. Apply: verify, spend inputs, persist outputs, C_i = k_i · B bound to operation_id.
    5. Wallet waits for T matching shares, pairing-checks, interpolates, unblinds.

    Public APIone POST /swapquote, then mint or melt
    Fan-outfull, for sharesfirst-healthy quote; full for mint/melt

    Replay is idempotent. A later window dies with TokenAlreadySpent. SIG_ALL is still the client-intent hole, not a missing swap step.

    27 Roster and federation config

    If you put a hostname in the constitution, changing it founds a new country.

    FederationId is SHA-256 over setup authorization, thresholds, and every member’s id, public URL, private URL, and identity key. There is no “change member 3’s DNS” operation.

    28 Crash resistance

    Peers can give you the book. Only your backup is the pen.

    There is no BIP39 seed that regenerates a federation member. A seat owns unique secrets. Lose them and you replace the federation.

    The book

    Peer-recoverable

    Journal from genesis, finalized bodies, materialized Cashu state, checkpoints, catch-up certificates, order digest + state digest. Empty DB + old secrets can genesis-replay in v1.

    The pen

    Not reconstructible

    Identity secret, BLS shares for every keyset including rotated ones, sealed FROST root share + sealing key, Bark receive secrets. Wrong seat fails activation / PoP.

    process crash, DB intact → ordinary restart lag / partition → catch-up, fail closed DB lost, secrets + snapshot → restore + audit + tail catch-up secrets lost → that seat is dead. new setup. readiness: no public submit, no FROST, no broadcast until caught up
