Problems Solved

Scope clarified

Minting, swapping, and melting are all explicit implementation requirements, including fake-wallet happy and unhappy paths.

Transport strategy clarified

Private REST is the first mint-to-mint transport, with Iroh left as the NAT traversal path for deployments that need it.

Identity split clarified

Member identity keys authenticate federation traffic; threshold BLS shares sign Cashu outputs.

Startup validation landed

Federation configs are rejected at startup when public roster data and local private member state do not match.

Mix-and-match guardrail started

The same mint quote cannot be paired with different blinded output sets, including through an overlapping NUT-29 batch, without producing a conflict before any future federation member signs.

Catch-up shape defined

Members can request journal entries from a missed index and verify order continuity through a chained digest.

Private API isolated

Federation routes mount under a separate private path only when mintd loads a valid federation config.

Consensus boundary testable

Operation ordering can be tested locally before replacing the decision source with peer quorum networking.

Signing gated by operation IDs

Signature-share payloads now carry the operation ID that authorized the share, preparing the mint paths to sign only after consensus acceptance.

Federation keyset boundary closed

Federation mode now treats Cashu keyset v3, CDK `KeySetVersion::Version02`, as mandatory for aggregate BLS keysets. Targeted standalone tests still build and rotate legacy non-federation keysets unchanged.

Standalone signer bypassed for federation minting

Federated mint requests no longer fall through to standalone blind signing after consensus; they return this member's threshold BLS share response instead.

Member catch-up route works against journal

The private REST scaffold can now serve accepted journal entries instead of returning a placeholder response.

Mint quote proposals carry payment requests

Federation mint quote operations now commit to both the wallet's request and the proposing member's quote response, including the payment request peers must persist.

Public mint paths can feed consensus

Axum mint quote, quote-check, and mint-submit handlers now prove consensus submission without changing wallet-facing REST payloads.

Mint share generation is isolated

Threshold share generation is now testable at the mint runtime boundary before changing wallet-facing response formats.

Threshold math baseline

The first implementation proves that any valid threshold subset aggregates to the same blind signature under the aggregate key.

Melt standalone-signature leak blocked

Federation melt requests no longer flow silently into the standalone finalization path for change outputs; member mode now fails closed until the consensus-backed spend-table executor owns proof verification, settlement, and change-share generation.

Aggregate melt proofs verified

Federated melt inputs now verify against the aggregate v3/BLS federation keyset instead of local standalone keysets before the fake-wallet payment saga is allowed to finalize.

Federated melt change signs as shares

Paid fake-wallet melts with overpaid inputs now derive change amounts, persist member-local blind signature shares, and expose those shares through the normal melt response shape for wallet aggregation.

Restore placeholders stay federation-safe

Restore requests can use NUT-09 zero-amount blinded output placeholders, but only against active aggregate v3/BLS federation keysets.

Proof state divergence is visible

The wallet connector no longer accepts a single member's check-state result; it requires threshold agreement and rejects mismatched spent, pending, or unspent views.

Offline replay has a consensus guard

Catch-up replay rejects wrong federation IDs, stale known digests, mismatched operation IDs, and broken journal digest chains before appending anything to the local order.

Payment observations use the peer API

The private REST client can submit canonical mint quote payment observation operations and checks that the peer response belongs to the exact operation sent.

Envelope tampering is isolated

Shared transport tests now reject unknown senders, wrong receivers, wrong federation IDs, stale sequences, body-hash mismatches, and signatures that do not match the claimed roster identity.

Private REST mutation requires roster auth

Route tests now prove that tampered operation payloads, unknown senders, wrong message kinds, and stale sequence numbers fail before the local consensus journal changes.

Accepted order survives storage

The federation journal row shape now preserves consensus order, digest continuity, local application status, quote conflict metadata, and member sequence watermarks across SQL round trips.

Restart loses less federation state

Storage-backed members now rebuild accepted operation order, digest continuity, operation conflict indexes, and member REST sequence watermarks when the mint runtime starts again.

Catch-up creates usable mint state

A member that learns a mint quote through catch-up now persists the quote locally, and accepted mint operations advance paid quotes to issued while storing the member's signature share for later lookup.

Catch-up spends swap inputs deterministically

A member that learns a swap through catch-up now verifies the aggregate input proof, marks it spent, stores the authorized output share, and marks the journal entry Applied without needing the original public REST request.

Catch-up can finalize fake-wallet melts

A member that learns an accepted melt through catch-up now executes the same federation melt state machine as the public route, ending with a paid quote, spent proofs, stored change shares, and Applied journal status.

Catch-up creates usable melt quotes

A member that learns a melt quote through catch-up now stores the consensus quote ID, payment method, invoice, amount, fee reserve, unpaid state, and Applied journal status without needing the original public REST request.

Delayed melt settlement is reconstructable

A member that learns a paid outgoing melt observation after a pending melt now finalizes the quote, spends proofs, stores change shares, records the payment proof, and marks both journal entries Applied.

Failed melt settlement rolls back cleanly

A member that learns an unpaid outgoing melt observation after a pending melt now removes saga metadata, releases pending proofs, returns the quote to Unpaid, and keeps the consensus journal applied.

Divergent peer history halts catch-up

Digest-bound catch-up requests and response validation reject a member history that already diverged, preventing a node from silently blending two accepted operation orders.

Lagging members fail closed before signing

Once a peer status reveals that a member is behind, public mint, swap, melt, quote, and observation submissions are blocked until peer catch-up restores a matching accepted-order digest.

Peer sync no longer depends on wallet traffic

Member recovery can now run independently of public wallet requests, and tests ensure a lower-height peer cannot clear a higher known lag condition.

Local federation setup is reproducible

Operators and tests no longer need to handcraft federation JSON: the mint daemon can generate a complete fake-wallet local roster, validate every private member config, and protect generated secret material with a local ignore file.

Restarted members stop replaying sequence one

The private peer client no longer starts every process lifetime at REST sequence 1, so receivers that persist signed-route watermarks are not forced to reject legitimate restarted members as stale senders.

Operator-visible sync state has a signed surface

Federation members now expose local consensus and sync-guard state through the existing authenticated private REST boundary, and mintd can query that surface as a signed operator smoke probe.

Generated rosters have a status probe

The trusted-dealer output can be checked without wallet traffic by pointing the status CLI at a generated member config or at explicit public/private federation JSON paths.

Process smoke has a reproducible entrypoint

Local federation bundles now carry their own smoke runner, so operators and tests have a single command for startup, signed status checks, and restart probing.

Smoke status fails on disagreement

The operator status probe no longer only prints member state; it can enforce ready and converged member views, giving the live process smoke a machine-checkable success condition.

Oversized operation DoS guard started

Consensus admission now checks operation-envelope size using the same canonical representation used for operation IDs, so formatted JSON differences cannot change whether members accept a proposal.

Catch-up no longer trusts raw peer ranges

When a peer returns missing journal entries over private REST, the response must include a signed session outcome from that roster member before the local node replays the entries.

Federation inspect CLI ready

`cdk-mintd federation inspect` validates public federation material, optionally checks a local member config against it, and prints roster plus v3/BLS aggregate keyset summaries without exposing private member material.

Sliding-window mint attack covered

A focused consensus regression now submits ABC, BCD, CDA, and DAB output sets for the same mint quote. The first accepted operation is replay-idempotent, all overlapping variants conflict on the quote key, and the journal keeps one canonical mint entry.

Naive threshold signing risk documented

A paired cdk-common test now intentionally bypasses consensus, has four members sign ABC, BCD, CDA, and DAB under different operation IDs, and proves the wallet can regroup enough shares for every output. This keeps the consensus-before-signing invariant concrete.

State digest scaffold exposed

Federation journals now compute a consensus-visible state digest that is distinct from the order digest and stable across local status updates. Private status and catch-up payloads expose it, Axum peer sync halts on equal-height state-digest mismatch, and mintd convergence checks enforce it.

Bounded operation admission ready

Federation operation envelopes now have a deterministic canonical-size limit. Oversized operations are rejected before consensus journal append, peer clients refuse to broadcast them, and signed private REST submissions leave sequence watermarks untouched when admission fails.

Signed catch-up outcomes ready

Private REST catch-up responses now carry member-signed session outcomes over returned accepted-operation ranges, operation IDs, range digests, and latest order/state digests. Peer clients reject non-empty catch-up data without a valid serving-member signature.

Signed session outcomes are durable

Mint storage now persists signed catch-up session outcomes alongside accepted journal entries, so restart and later quorum verification can inspect which member attested to each replayed range.

Milestone map expanded

The dashboard now renders 24 explicit implementation-plan milestone points, with no grouped shorthand ranges.

Open Problems And Risks

Consensus crate choice

Need to decide when to move from in-memory deterministic consensus to an AlephBFT-backed engine.

State-machine extraction

Mint issue, swap, and melt logic must be refactored carefully so standalone behavior remains unchanged.

Networked recovery semantics

The private REST client can replay missed journal entries over signed routes, and SQL storage now restores accepted entries plus sequence watermarks at startup. Multi-operation offline catch-up covers mint, swap, melt, and payment observations. Lagging members now fail closed before public signing, router startup launches a peer recovery loop, mintd can generate runnable local member configs plus a guarded local smoke script, restarted private REST clients no longer replay low sequence numbers, and local sync plus state-digest health is queryable from mintd over signed private REST. The remaining work is to run the generated smoke script in an environment that allows loopback listener binding.

DKG timing

Trusted-dealer key shares come first; dealer-free DKG waits until MVP federation correctness is proven.

Architecture Decisions

Fedimint as reference, CDK simplicity as constraint

Use Fedimint for invariants and patterns, but keep smaller CDK-native designs when they preserve the same safety properties.

Private REST first

REST is the MVP member transport because it fits existing CDK server/client patterns and is easy to test locally.

Consensus before signing

No member may return a usable blind signature share until the exact operation has been accepted by consensus.

Federation keysets are v3/BLS-only

Aggregate federation keysets use Cashu keyset v3 IDs and BLS public keys exclusively; v1/v2 keysets remain standalone-only unless a future protocol explicitly adds support.

Feature-off compatibility

The first Rust scaffold is gated so normal standalone builds do not see federation mint fields or APIs.

Trusted-dealer first

Milestone 1 starts with local polynomial shares so later DKG work can reuse the same share verification and aggregation code.
