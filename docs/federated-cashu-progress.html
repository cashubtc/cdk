Architecture Decisions

Fedimint as reference, CDK simplicity as constraint

Use Fedimint for invariants and patterns, but keep smaller CDK-native designs when they preserve the same safety properties.

Private REST first

REST is the MVP member transport because it fits existing CDK server/client patterns and is easy to test locally.

Consensus before signing

No member may return a usable blind signature share until the exact operation has been accepted by consensus.

Runtime-owned consensus engine

Server state depends on a small consensus runtime wrapper and trait surface, so the current in-memory ordering source can be replaced without rewriting public routes, storage replay, or catch-up handlers.

Simulate network faults before BFT

The CDK-native simulator gives deterministic coverage for message delay, duplication, reordering, offline catch-up, and quorum refusal before adding a heavier real consensus backend.

Bounded consensus admission

Consensus items are canonicalized and size-checked before batching, and duplicate operation hashes are collapsed while they are still pending.

Backend-owned finalization delivery

Federation submissions now deliver accepted entries through a queue-backed finalization task; the inline path remains for focused fixtures, while router-created state uses the same apply-and-notify boundary future consensus engines can target.

Adapter before BFT

The first backend adapter is simulator-backed and operation-focused, while the AlephBFT adapter runtime and Axum helper now expose explicit preview, quorum-broadcast, bounded driver tick, queue-and-wait submit, pending sequence handoff, exact-drain, external-finalization calls, and signed local-status counters so future BFT wiring cannot mistake local admission for accepted consensus order or hide queued/finalized adapter state from operators.

Digest format before DB wiring

Materialized state convergence starts with a backend-neutral row snapshot and deterministic hash before individual storage adapters are asked to enumerate their mint state rows.

Status digests are materialized

Private status and signed catch-up evidence fail closed if database rows cannot be read, and peers compare both accepted order and applied mint-state digests before reopening signing paths.

Federation keysets are v3/BLS-only

Aggregate federation keysets use Cashu keyset v3 IDs and BLS public keys exclusively; v1/v2 keysets remain standalone-only unless a future protocol explicitly adds support.

Real payment observations fail closed

Fake-wallet testing keeps one-observation finality, while real-backend policies require a configured quorum, reject single-observation finality, and now have pure matching/conflicting observer evaluation ready for DB-backed persistence.

Feature-off compatibility

The first Rust scaffold is gated so normal standalone builds do not see federation mint fields or APIs.

Trusted-dealer first

Milestone 1 starts with local polynomial shares so later DKG work can reuse the same share verification and aggregation code.
